HTTP 压测工具横向对比报告

对比对象：loadtester（本项目，Rust release 构建） oha 1.16.0（GitHub 16k+ Star，Rust） ApacheBench 2.3（Apache httpd 官方自带，C）
环境：Windows 11 / 本机回环 127.0.0.1 / 目标服务：Python ThreadingHTTPServer（HTTP/1.1 + keepalive，连接队列 256）
测试条件：三个工具顺序执行、直连（已剥离代理环境变量干扰）、同一目标服务、相同负载参数 · 采集时间 2026-09-25

一、测试 1：满负荷吞吐（GET /ping，n=20000，并发 50，HTTP/1.1 keepalive）

目标服务本身是瓶颈（约 5200 QPS 上限），三个工具测的是"同一堵墙"，因此 QPS 差异主要反映工具自身开销与连接策略。ab 未启用 keepalive（Windows 下开启会触发 apr_pollset_poll 超时的已知问题），每请求重建 TCP 连接，故 QPS 与延迟明显吃亏。

五、结论

  • 性能同档：满负荷下 loadtester 与 oha 实测 QPS（5106 vs 5199）与 p99（11.49 vs 11.19ms）差距在 2% 以内——达到与市面最流行的现代 Rust 压测工具同一性能档位；两者都显著优于 ab（ab 短连接模式下 QPS 只有 45%，且不支持 HTTP/2）。
  • 限流达标：令牌桶限流实测偏差 -0.32%（目标 500 QPS，5 秒窗口），验证了核心卖点"精准 QPS 限流"。
  • 计时准确：对固定 200ms 延迟接口，三者 p50 误差均 <1.5ms，loadtester 的 HdrHistogram 纳秒精度统计可信。
  • 差异化优势：相对 oha/ab，loadtester 独有 ①数据集随机化压测 ②YAML 配置合并 ③p99 阈值 CI 退出码 ④JSON 原始样本导出——更贴合"团队接口回归 + 流水线卡点"场景。
  • 发现的改进点：Reqwest 默认跟随 HTTP_PROXY 环境变量，本机带代理时会绕道代理并改写请求路径（本次测试已剥离）。建议：① 增加 --noproxy/默认对回环地址不走代理；② 补 ALPN 协商的 HTTP/2（当前 prior-knowledge）。
口径说明：① 目标服务为 Python 单机实现，QPS 上限约 5200，三工具均受同一瓶颈约束；② 单轮测试，未做多轮取均值；③ ab 在 Windows 下 keepalive 模式有已知缺陷，故按其默认短连接模式测试，这部分差距是"连接策略差异"而非纯性能差距。
